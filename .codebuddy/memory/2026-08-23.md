# 2026-08-23

## 分红年息计算改为事件驱动累加（支持一年多次分红）
- 用户参照小程序：年股息 = 每笔派息事件累加，而非单值年化。
- 改动 `app.js`：
  - `calcHolding`：预计年股息(annualDiv)与股息率(yield)改为优先用「最近12个月内派息事件的每股合计 × 股数」；无事件时回退 `dividendBasis.perShare`（手动填的全年合计兜底）。回本进度/累计收息本就遍历 events 累加，已正确。
  - `fetchDividendBasis`：由返回单条改为返回**多条**有效记录数组（同代码一年多次分红都返回）。
  - `autoFetchDividends`：逐条建 `dividendEvents`（按 exDate+code 去重），不再覆盖单值 `dividendBasis`。
- 手动"补分红"按钮仍写 `dividendBasis.perShare`，作为无事件时的全年合计兜底，语义兼容。
- 验证：read_lints 无错误。

## 修正：防止跨年度分红相加（用户指出"应算中报+年报同一年，而非两年相加"）
- 根因：东财 `RPT_SHAREBONUS_DET` 返回历年记录，原逻辑把多年度记录全建事件 → 跨年混加。
- 修正（`app.js`）：
  - `fetchDividendBasis`：返回前按「除权年份」归并，只保留**最近一年份**的多条记录（中报+年报同属一年正确相加）。
  - `calcHolding`：预计年股息改为按除权年份分组、取最大年份合计；无事件回退 `dividendBasis.perShare`。
  - `renderCalendar`：年度派息预测同样按「最近除权年份」合计，不再硬卡 currentYear。
  - `autoFetchDividends`：重建前清掉该代码 note 含"分红"的旧抓取事件（不动手动录入事件），避免旧年堆积污染累计收息。
- 验证：read_lints 无错误。

## 严重 bug 修复：PRETAX_BONUS_RMB 单位（每10股 vs 每股）
- 用户指出"每10股分红，按每股算了"。实测东财 RPT_SHAREBONUS_DET：PRETAX_BONUS_RMB 与方案文本"10派XX元"的XX完全一致 → 单位是**每10股**，需 ÷10 才是每股。
- 之前直接当 perShare 用 → 年股息放大 10 倍（如云南白药 10派15.83 被算成 15.83/股而非 1.583/股）。
- 修正（`app.js` `fetchDividendBasis`）：`perShare: parseFloat(d.PRETAX_BONUS_RMB) / 10`。
- 验证：read_lints 无错误。

## 修正：财年归并（替代之前的除权年份归并）
- 发现用除权年份归并仍错：A股中报与年报除权日常跨自然年（茅台 2025中报除权2025-12-19、2025年报除权2026-06-26），按除权年归并会把同财年拆开。
- 改用 REPORT_DATE（报告期）年份作为财年 `fy` 归并：中报(2025-09-30)与年报(2025-12-31)同属2025财年正确合并。
- 改动：`fetchDividendBasis` 用 `REPORT_DATE` 取财年并带入 `fy`；`autoFetchDividends` 建事件写 `fy`；`calcHolding` 与 `renderCalendar` 改按 `fy` 分组取最大财年合计。
- 注：用户浏览器 localStorage 可能残留旧 `dividendBasis` 兜底值与无 `fy` 旧事件，需清 localStorage 或隐身窗口验证。
